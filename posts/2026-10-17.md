Most LTS releases are quiet. [Node.js 24.22.0](https://nodejs.org/en/blog/release/v24.22.0) isn't: its notable-changes list is almost entirely `SEMVER-MINOR` additions, which means a lot of new surface area landed on the LTS line in one go. I'm going to walk through the pieces I'd actually reach for, and then deal with the more urgent news.

## Utilities you've probably written yourself

The release adds `util.debounce` and `util.throttle` (both from #65899), plus `util.markPromiseAsHandled`. Every Node backend I've seen has a hand-rolled debounce somewhere, usually inside a file watcher, a webhook batcher, or a "save after the user stops typing" handler. Having it in core removes one more tiny dependency.

The release notes list the names, not the signatures, so check the `util` docs for your version before swapping your own helper out. In particular, confirm how it handles trailing calls and cancellation, since that's where homegrown versions differ the most.

## SQLite gets proper cleanup

`StatementSync.prototype.close()` and `StatementSync.prototype[Symbol.dispose]()` (#64232) are the ones I like best. If you use `node:sqlite` for scripts, tests, or small local tools, you can now release a prepared statement deterministically instead of waiting for garbage collection. The `Symbol.dispose` part means it should work with `using` declarations where your toolchain supports them:

```js
import { DatabaseSync } from "node:sqlite";

const db = new DatabaseSync(":memory:");
db.exec("CREATE TABLE t (id INTEGER PRIMARY KEY, name TEXT)");

{
  using insert = db.prepare("INSERT INTO t (name) VALUES (?)");
  insert.run("hello");
} // statement is disposed here
```

That's a sketch based on the method names in the release notes, so run it against 24.22.0 before relying on it.

## Crypto and metrics

Crypto got the biggest share of the changes: `crypto.parsePKCS12()`, a generic MAC API, discovery of ciphers and hashes from OpenSSL providers, and SIV and GCM-SIV modes in the Cipher/Decipher APIs. `parsePKCS12()` is the one that matters for integration work. If you've ever had to unpack a `.p12` client certificate for mutual TLS to a partner API, you know the usual answer is shelling out to `openssl` or pulling in a library.

On the `perf_hooks` side, `Histogram` gains a sliding-window variant, a `meanCI` API, and CBOR export/import for exchanging histograms. That reads like groundwork for better latency reporting across worker threads or processes. I haven't used it yet, so I'll hold my opinion.

## The Current line is a different story

[Node.js 26.12.0](https://nodejs.org/en/blog/release/v26.12.0) lists only two notable changes: `http.websocketMask()`/`websocketUnmask()`, and throwing when WebAssembly or RX support is missing. The rest is a long tail of commits, including a series of crypto key-locking removals. If you're on 24 LTS, you aren't missing much by not tracking 26 right now.

## Plan around October 21

The more time-sensitive item is the [security release announcement](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). The project says it will ship new versions of the 26.x, 24.x, and 22.x lines on or shortly after Wednesday, October 21, 2026, and that the highest severity issue fixed is HIGH on all three. Details aren't public yet, and end-of-life versions are always affected.

My take: don't spend this week chasing 24.22.0 as a destination. If you want the new APIs, take them, but plan to be on the patched release as soon as it ships. If you run anything on an EOL line, that's the thing to fix first, because it won't get this patch at all.
