This week's whole feed is one Node security release, and I've already written about the hostname-parsing theme twice. So for the Friday roundup, here are the entries in the [advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that got less attention, with a sentence or two on each.

## Same random values in every process

The advisory says `crypto.randomUUID()` and `randomInt()` entropy caches get saved into user-land startup snapshots and single executable applications (SEAs), so every process repeats the same values (CVE-2026-106074, medium). The release notes list the fix as "reset random caches across snapshots."

If you ship a SEA or use startup snapshots, this is the one I'd check first. Duplicate IDs don't announce themselves; they show up later as a weird collision. The 26.x, 24.x and 22.x notes all list it.

## Keep-alive sockets and early responses

CVE-2026-105481 (medium) is described as a keep-alive socket processing a response that was written before the request was sent. The fix is listed as "http: ensure agent data guard works without I/O." I'd want to read the full advisory text before saying more about exploitability, but it's a good reminder that HTTP client agents are stateful, and connection reuse is where that state lives.

## The permission model keeps getting patched

Two entries touch the permission model: `realpathSync` now checks it (CVE-2026-106073, low), and the advisory lists a filesystem over-grant via wildcard radix lookup (CVE-2026-106071, low). Both are low severity. Still, if you're leaning on `--permission` as a sandbox, treat it as defense in depth rather than a boundary. Two fixes in one release is a signal about how young the feature is.

## ZIP headers

CVE-2026-106070 (low) covers `ZipFile` returning attacker-controlled prefix bytes after failed header validation. The fix is "avoid caching invalid ZIP local headers." It's listed in the 26.x notes only, as far as I can tell. I didn't see it in the 24.x or 22.x lists.

## The Brotli one

CVE-2026-111497 is high severity: the advisory heading calls it a Brotli decoder out-of-bounds write that permits remote code execution. It was fixed by cherry-picking an upstream Brotli commit in all three lines. Anything that decompresses untrusted Brotli, such as HTTP responses or uploads, is the exposure to think about.

## Versions to land on

- [26.12.1](https://nodejs.org/en/blog/release/v26.12.1) (Current)
- [24.22.1](https://nodejs.org/en/blog/release/v24.22.1) (LTS)
- [22.23.4](https://nodejs.org/en/blog/release/v22.23.4) (LTS)

All three also bump c-ares to 1.34.9 and refresh root certificates to NSS 3.131.1. The 24.x and 22.x notes add OpenSSL 3.5.9 and timezone data 2026e.

## My take

Skip the high-severity list for a minute and read the mediums and lows. The patch is the same either way, but the entries about snapshots, SEAs and agents tell you which features your own deployment depends on that you may not have audited. Have a good weekend.
