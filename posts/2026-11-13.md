The Node release feed was loud this week, and almost all of it is one event: the November 11 security release. Here's the skim version, plus the one alpha worth a glance. My feeds mostly failed to load this morning, so everything below comes from the Node.js release notes themselves.

## The November 11 security release

[The advisory](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases) covers the 22.x, 24.x and 26.x lines. By my count from the release notes it lists seven High, eight Medium and a handful of Low issues, and most of them are in HTTP/2 or TLS. If you run a Node server that terminates either one, this is a patch-this-week release.

A few that stood out:

- **HTTP/2 remote abort (CVE-2026-123863, high).** An unauthenticated client can crash a default `http2` server by getting an `Http2Stream` with nghttp2-allocated header buffers to outlive its session, which trips a `CHECK_EQ` assertion. The advisory says the trigger only needs a handler that responds before the request body has ended, which it calls typical. It's described as a variant of CVE-2024-27983 that the earlier fix missed. The advisory lists 24.x and 26.x as affected.
- **Zero-length TLS write (CVE-2026-123864, high).** A zero-length write re-enters `llhttp_execute()`, and the advisory says the server copies its own heap into the request body. That's the kind of bug that makes you want a closer read of the advisory. It affects 22.x, 24.x and 26.x.
- **TLS renegotiation changing the SNI (CVE-2026-123872, high).** A client can change the servername unilaterally and bypass client certificate authentication. If you do per-host mTLS, read this one carefully. The fix includes disabling resumption for mTLS with no session id context.
- **`https.Agent` cross-policy session reuse (CVE-2026-123877, medium).** The advisory describes a certificate validation bypass through TLS session reuse across policies. That one is about outbound requests, so it matters even if you don't serve anything over HTTP/2.
- **Proxy credentials in error messages (CVE-2026-123871, medium).** Credentials could show up in `ERR_PROXY_INVALID_CONFIG` messages. That's an easy way to leak a secret into your logs.

Two smaller notes. The permission model gets several Low fixes, including a leak of denied descendants' names in recursive `fs.watch`. And HTTP/2 shows up so often that I'd treat it as the area to watch, not a one-off. Several of these are use-after-free or lifetime bugs around stream teardown.

## Which versions to be on

The patched releases are all dated 2026-11-11:

- [26.13.1](https://nodejs.org/en/blog/release/v26.13.1) ("Lithium")
- [24.22.3](https://nodejs.org/en/blog/release/v24.22.3) ("Krypton")
- [22.23.5](https://nodejs.org/en/blog/release/v22.23.5) ("Jod")

The 26.x notes list dependency bumps too: llhttp 9.4.4, undici 8.12.4, sqlite 3.54.1 and brotli 1.2.1. Per the advisory, llhttp is updated on 22.x, 24.x and 26.x, undici on 24.x and 26.x, and sqlite on 22.x and 24.x.

A practical check is to bump the base image tag, rebuild and run `node -v` in the container. Pinned Docker tags are the usual place a security release gets missed.

## The 27.0.0 alpha

[27.0.0-alpha.0.1.0](https://nodejs.org/en/blog/release/v27.0.0-alpha.0.1.0) landed on November 12. It's an alpha, so don't ship it, but the notable changes are a decent preview:

- `subprocess.timedOut` on `child_process`.
- X.509 generation with CSR support in `crypto`, plus explicit inspection guards.
- `dns.lookup()` coalescing identical concurrent requests.
- The HTTP parser batching body spans per execute.
- A compile cache for the VFS modules in single executable applications.
- Streams preloaded into the worker startup snapshot.

The `dns.lookup()` coalescing is the one I'd test first if you do a lot of repeated lookups, because it changes request behavior in a way that's invisible until it isn't. The HTTP parser change is also interesting next to this week's llhttp-related fixes, though I wouldn't read anything into the timing from the notes alone.

## Takeaway

Patch, then check your container images. After that, if you use client certificates with SNI-based routing, it's worth rereading how your setup handles renegotiation and resumption.
