Last week's Node security release (26.12.1, 24.22.1 and 22.23.4) has already been picked apart for its TLS and DNS hostname bugs. I'm not going to repeat that. Start the week by patching, then spend a few minutes on the three things in the [advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that are easier to miss and that hit different kinds of apps.

The patch itself is a boring decision. The advisory lists ten CVEs, the highest severity on every line is High, and the fixed builds are [26.12.1](https://nodejs.org/en/blog/release/v26.12.1), [24.22.1](https://nodejs.org/en/blog/release/v24.22.1) and [22.23.4](https://nodejs.org/en/blog/release/v22.23.4). If you're on an end-of-life line, you're affected too, and the advisory says so plainly.

## 1. Brotli: the one that can corrupt memory

CVE-2026-111497 is the High-severity item I'd read first if you accept compressed input. Per the advisory, the Brotli decoder in `node:zlib` treats an invalid block switch as "need more input", which leads to an out-of-bounds write past an 8-byte buffer. The listed consequences range from a crash to memory disclosure to remote code execution. It affects all three lines.

Most of us think of Brotli as something the server *sends*. The exposure is on the decode side:

- API endpoints that accept `Content-Encoding: br` request bodies
- Proxies or scrapers that decompress upstream responses
- Anything that unpacks user-supplied `.br` files in a worker

If you call `zlib.brotliDecompress` or `createBrotliDecompress` on bytes you don't control, treat this as urgent rather than routine. A quick way to see whether you're exposed:

```bash
grep -rnE "brotliDecompress|createBrotliDecompress|BrotliDecompress" src/ \
  --include=*.js --include=*.ts
```

That won't catch frameworks that decode for you, so check your body-parsing middleware's supported encodings as well. If a middleware accepts `br` and you never intended it to, turning it off is a reasonable stopgap until the patch lands.

## 2. randomUUID() repeating itself in snapshots

CVE-2026-106074 is Medium, and it's the sort of bug that only bites a specific deployment style. Entropy caches for `crypto.randomUUID()`, `randomUUIDv7()` and `randomInt()` get saved into `--build-snapshot` images and single executable applications that use `useSnapshot`. Every process started from that snapshot then repeats the same values.

That matters if you're using snapshots to cut startup time, which is the whole reason to use them. Think of serverless functions or CLI tools shipped as SEAs. Anything that uses those functions for IDs, idempotency keys, or tokens could collide or become predictable. The release notes describe the fix as resetting the random caches across snapshots.

I'd rebuild any snapshot or SEA artifacts on a patched Node. Patching the runtime on your servers isn't enough, because the bad state is baked into the artifact you already built. That's an easy step to forget.

## 3. The permission model keeps leaking

Two Low-severity items concern the experimental-turned-real permission model:

- CVE-2026-106073: `fs.realpathSync()` lacked read-permission checks, so code could check existence, resolve symlinks, and enumerate paths outside the permitted directories. The advisory calls it an incomplete fix of CVE-2026-21715.
- CVE-2026-106071 (26.x only): a wildcard rule can match shorter paths, so `--allow-fs-read=/etc/passwd.*` also allows `/etc/passwd`, when the wildcard grant sits directly under the tree root.

Neither is dramatic. What I take from them is that the permission model is still a seatbelt, not a sandbox. If you run untrusted code, such as plugins, user scripts, or AI-generated tooling, with `--permission`, keep a process or container boundary around it. The advisory's wording of "incomplete fix" shows up again here.

## The pattern worth noticing

Count the "incomplete fix" and "regression" notes in the advisory. The DNS NUL-byte bug is an incomplete fix of CVE-2026-48930. The non-ASCII digit IP bug (CVE-2026-105483) is a regression after the CVE-2026-48618 fix. The HTTP agent keep-alive issue (CVE-2026-105481) is an incomplete fix of CVE-2026-48931. Together with `realpathSync`, that's four of the ten that are follow-ups to earlier patches.

I don't read that as sloppiness. A lot of security research is now aimed at re-testing recent fixes, and the advisory credits OpenAI Codex Security, with two named researchers, for the Brotli report. What it does mean for us is that "we patched that CVE last month" isn't a reason to skim the next release. Re-read the advisory for the same components.

## What I'd do today

1. Upgrade to 26.12.1, 24.22.1 or 22.23.4, depending on your line. Check `node -v` in your container images, not just on your laptop.
2. Search for Brotli decode paths on untrusted input and confirm they're covered by the new build.
3. Rebuild snapshots and SEAs.
4. If you rely on `--permission`, add a real isolation layer around untrusted code, or confirm you already have one.
5. Note the dependency bumps: c-ares, Undici, OpenSSL on 24 and 22, SQLite on 22, and the ca-cert update tied to the eMudhra intermediate CA compromise. If you pin or vendor any of those, check whether you have to do anything on your side.

I haven't read the diffs for these fixes, only the advisory and release notes, so the details above are as the advisory describes them.
