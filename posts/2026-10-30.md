It's a Node-only Friday. Every other feed I normally pull from was unreachable when this was put together, so this roundup is three Node.js release posts. One of them is the interesting one.

## Node.js 27.0.0-alpha.0

[The first 27 alpha](https://nodejs.org/en/blog/release/v27.0.0-alpha.0.0.0) landed on 2026-10-29. It's an alpha, so nobody should be shipping it, but the changelog is a decent preview of what your upgrade PR will look like. Most of the notable changes are tagged SEMVER-MAJOR, and a few of them change defaults rather than removing APIs, which is the kind that gets through a green test suite and shows up in production.

### The V8 bump is the headline

V8 goes to 15.6 (15.6.75.13), up from 14.6 in Node 26. The language additions enabled by default are `Math.sumPrecise()`, `Iterator.prototype.join()`, `Iterator.prototype.includes()`, `Iterator.zip()` and `Iterator.zipKeyed()`, plus `Intl.Locale.prototype.variants`. `import defer`, immutable `ArrayBuffer` and a RegExp buffer-boundaries feature are there too, but only behind flags.

The iterator helpers are the ones I'd actually use. Zipping two iterators without materializing arrays is something people currently write by hand or pull a utility for.

### Memory defaults changed

This is the one to read twice:

- With no `--max-old-space-size`, the default heap limit is now half of physical memory, clamped between 256 MB and 4 GB.
- Memory held by `Buffer` and `ArrayBuffer` instances now counts toward that limit.

The release notes tell you plainly: if you relied on the old defaults, set `--max-old-space-size` explicitly. I'd go further and say that anything that moves lots of binary data, such as proxies, file upload handlers or webhook receivers that buffer payloads, should be load tested against this before 27 goes stable. Moving buffers onto the heap budget is the sort of change that is correct in principle and surprising in a container with a small memory limit. I haven't tested it, so treat that as a thing to check, not a finding.

### Serialization and observable behavior

A few more V8-side changes worth knowing about:

- `v8.serialize()`, `structuredClone()` and `postMessage()` use a new format that older Node.js releases can't read. If you pass serialized data between processes or services on different Node versions, that's a rollout-ordering concern.
- `v8.cachedDataVersionTag()` and the compile cache now change on every V8 patch in Node, not just on V8 version changes.
- `Math` methods use LLVM's libm and may differ in the last bit, and `Math.random()` sequences change for a given `--random-seed`. Snapshot tests that pin floating-point output are the obvious casualty.
- `error.stack` is no longer looked up through the prototype chain.
- Heap snapshots include more (internal objects, numeric values, full script sources), take about twice as long and produce files about twice as big.
- asm.js is no longer compiled to WebAssembly, and `--experimental-wasm-<name>` flags become `--wasm-<name>`.

### The HTTP changes

Several of the semver-major commits touch `http` and `http2`, and these are the ones that matter for API and webhook services:

- The default `keepAliveTimeout` goes up to 65 seconds. That is longer than the 60-second idle timeouts that load balancers commonly use, which is presumably the point: fewer races where the balancer reuses a connection the server just closed. (The reasoning is my inference; the changelog just lists the change.)
- `req.headers` gets a null prototype. Code that calls `req.headers.hasOwnProperty(...)` will break, and `in` or `Object.hasOwn` is the safer spelling.
- Responses that exceed the header limit are rejected, and `addTrailers` after finish is rejected.
- Instantiating `http` classes without `new` is runtime-deprecated, and the `_http_*` modules are deprecated.
- `http2` gets larger default window sizes.

### Crypto and build cleanup

There's a big batch from Filip Skokan: OpenSSL 3 or later is now required, the bundled FIPS provider build and OpenSSL engine support are gone, and the sources are upgraded to OpenSSL 4.1.0. Several old deprecations (DEP0093, DEP0198, DEP0203, DEP0204) move to end-of-life, and calling `Hmac.digest()` more than once is runtime-deprecated. New input and output encoding validation in the crypto APIs could turn previously tolerated sloppy calls into thrown errors. Intel macOS drops to experimental support.

### Smaller items

- `fs.glob` is implemented natively.
- The `domain` module is runtime-deprecated and ported to `AsyncLocalStorage`.
- `dns` no longer consults the hosts file in reverse lookups, and `dgram` skips the custom lookup for literal IP addresses.
- npm is upgraded to 12.1.0.

## Node.js 26.13.0: the LTS switch

[26.13.0](https://nodejs.org/en/blog/release/v26.13.0) is the release where 26.x becomes LTS, codename 'Lithium', supported through the end of April 2029. According to the notes there are no changes from 26.12.1 beyond metadata like the `process.release` object. One thing from the notes worth repeating if you're coming from 24 or 22: since Node 25 the official Linux binaries are linked against `libatomic`, which you may need to install separately depending on your distribution. That will break a minimal image if you swap the base layer and don't rebuild thoughtfully.

## Node.js 24.22.2: a small patch

[24.22.2](https://nodejs.org/en/blog/release/v24.22.2) is a short one. Mostly V8 backports and cherry-picks, plus one `stream` fix: keeping the async context of parked writes. If you use `AsyncLocalStorage` for request-scoped logging or tracing and write to streams under backpressure, that one is worth reading about.

## The takeaway

If you maintain services on Node, the 27 alpha is worth an afternoon of skimming now, not at stable. The two things I'd test first are the heap defaults and the HTTP header and timeout changes, because both can change behavior without a single line of your code changing.
